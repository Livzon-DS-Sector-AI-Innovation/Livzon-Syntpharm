# 能源月度交叉表字段映射对照表

> 范围：**只覆盖月度交叉表导入器** `app/modules/energy/bitable_cross_import.py`（`energy_monthly_records`）。
> 日采集表 `bitable_daily_import.py` 与车间主数据同步 `bitable_sync.py` 不在本文范围内。
> 变更背景与验收结果见 [energy-workshop-unification.md](./energy-workshop-unification.md)。

## 📋 表结构契约

导入入口是 `POST /api/v1/energy/sync/bitable/cross-import`，后台任务执行，按 `month`（`YYYY-MM`）或 `year` 触发。

| 契约项 | 代码位置 | 规则 | 源表不符合时的后果 |
|---|---|---|---|
| 数据表命名 | `import_month` / `import_year` | 单月按表名**全等**匹配 `YYYY-MM`；按年导入用 `str(year) in name and ("-" in name or len(name) == 6)` | 表名写成 `2026-6` 或 `2026年6月` 时该月**静默不导入** |
| 行主字段 | `_get_main_field_value` | 只认 `各车间电用量明细`、`各车间蒸汽用量明细`、`各车间自来水用量明细表` 三个列名（注意第三个以「表」结尾），取第一个非空值作为车间名 | 改列名 → 整行读不到，该 section 无数据 |
| 能源 section 切换 | `ENERGY_SECTION_PATTERNS` | 用正则匹配标题行：`各车间蒸汽用量明细` → steam、`各车间自来水用量明细` → water、`各车间天然气用量明细` → natural_gas | **电力 section 没有标题行**，解析器默认从 electricity 开始 |
| 日期表头 | `_parse_cross_table` 中 `main_value == "日期"` 分支 | 只把 `列*` 前缀的字段当日期列 | 手工把列改名成日期，该列数据丢失 |
| 日期格式 | `_parse_date_header` | 三种：`2026-06-02` 单日期、`2026-05-30-06-01` 跨月范围、`2026-07-01-03` 同月范围；`/` 会先换成 `-` | 其它写法解析为 `None`，整列跳过 |
| 单位 | `unit_map` | electricity `kWh`、steam `t`、water `m³`、natural_gas `Nm³`；单位行（`车间`）本身跳过 | — |
| 自来水子类别 | `main_value == "车间" and expect_subcategory_row` | 水 section 每个日期拆「凉水塔用量」与「车间生产用水量」两列，按日期**相加成一个数** | 这是正确行为，不要改成两条记录 |
| 天然气识别 | `"天然气" in main_value` 分支 | **没有独立 section 标题**，靠子串把 `current_energy_type` 切到 natural_gas；含 `总表`/`合计`/`总量` 的行跳过 | 见「已知缺陷 5」 |
| 汇总行跳过 | `SKIP_WORKSHOP_PATTERNS` | `合计\|小计\|总计\|总电量\|车间总计\|误差\|蒸汽总量\|总数\|市政总表\|全厂\|汇总` | 新增汇总行若不在此列表内会被当成车间入库 |
| 零值 | `if value is not None and value > 0` | 只有 **大于 0** 才落库 | 0 与「未填写」无法区分；把某条改成 0 不会删除既有记录 |
| 落库判重 | `import_month` | 按 `(workshop_id, energy_type, record_date)` 存在即更新 `value`/`unit`/`date_range_end` | — |

### 车间名解析链

```
源表原始叫法
   ↓ _normalize_workshop_name      strip()；纯数字补「车间」（101 → 101车间）
   ↓ WORKSHOP_ALIASES / 「车间映射」表   精确字符串比对（比对前 strip），sheet 优先
   ↓ _get_or_create_workshop       按 name 查 → 按 code 查 → 都补 is_deleted == false → 新建
```

**三步必须同时成立**：只改数据不改导入器，下次导入会立刻把别名车间重新建出来。

## ⚠️ 已知缺陷

1. **`name` 与 `code` 共用命名空间**：`_get_or_create_workshop` 用同一个字符串先查 `name` 再查 `code`。`uq_energy_workshop_code` 只锁 `code` 且**不含 `is_deleted`**，软删除行继续占着编码，日后重建同名车间会直接撞唯一约束。合并脚本已用 `code || '#merged#' || <uuid前缀>` 让出编码。
2. **`category` 实际全是 `workshop`**：`_get_or_create_workshop` 用默认参数，导入器从不传分类，`WorkshopCategory` 的四个取值（见 `models.py`）形同虚设。建议归类见下表。
3. **`import_year` 年度合计恒为 0**：`import_year` 累加 `result["created"]` / `result["updated"]`，而 `import_month` 返回的键是 `total_created` / `total_updated`。数据照常入库，只是统计数字错。
4. **唯一约束不含 `date_range_end`**：`uq_energy_monthly_record (workshop_id, energy_type, record_date)`，同一车间同一天但日期范围不同的两条表计行会互相覆盖。
5. **天然气靠子串识别且永久改写 `current_energy_type`**：气数据实际挂在**汽 section 的尾部**（`RTO(天然气）`、`天然气总表（Nm³）`），源表也没有 `各车间天然气用量明细` 标题行。当前布局里气行之后没有汽行，所以恰好无害；一旦源表把气行插到汽 section 中间，其后所有汽行都会被记成天然气。
6. **「车间映射」表尚未创建**：`_load_workshop_alias_map` 找不到该表时 `logger.warning` 并回退代码常量。目前生效的是常量。
7. **0 值不落库**：见上表「零值」。

## 🔍 常见问题

**Q：月度记录里选「质量控制部」为什么看不到水量？**
A：历史上水侧写 `QC`、电侧写 `质量控制部`，被建成两个车间；车间筛选按 `workshop_id` 精确过滤，两个实体的记录互斥。已通过「别名解析 + `is_deleted` 过滤 + 数据迁移」三项一起修掉，现在只有一个 `质量控制部`，电与水都在上面。

**Q：`/energy` 区域分布饼图的百分比为什么之前看不懂？**
A：电（kWh）、水（m³）、汽（t）、气（Nm³）混在一张饼图里算占比没有物理意义。现在后端 `distribution` 每个点带 `energy_type`，前端在卡片内用分段控件按 电/水/汽/气 分开画。

**Q：RTO 为什么同时有电和气？**
A：RTO 是一台独立的部门设备，源表把它的电耗记成 `RTO用电`、气耗记成 `RTO(天然气）`。导入器曾经**直接跳过** `RTO用电`（约 16,834 kWh/月，占全厂电 0.7%），那是丢数据而不是防重复计数；现在两条都归到同一个 `RTO` 实体。

**Q：饼图切片数比源表车间数少？**
A：正常。饼图只画**所选时间范围内有非零值**的车间。例如近 30 天 `103车间`、`环保中心` 用汽为 0，`动力车间` 用水为 0，于是汽只有 12 片而不是 14 片。

**Q：源表新增了一个同义叫法，要改哪里？**
A：优先在「车间映射」表加一条别名（改数据不改代码）；表还没建就先加到 `WORKSHOP_ALIASES`，然后**必须**在 `scripts/migration/merge_energy_workshop_aliases.py` 的 `WORKSHOP_UNIFICATION` 里补一条并执行，否则库里已经建错的实体会继续存在。
