# ADR 002: 设备批量导入 v4 - 增量更新与审计日志架构

## 状态
Accepted

## 背景
财务部门需要定期重新评估设备价值（当前成本、账面净值），而现有的 v3 导入功能在遇到已存在资产时会直接跳过，无法实现增量更新。此外，系统缺乏对低价值辅助设备的管理支持，且没有完整的审计追踪来满足财务合规要求。我们需要一种既能保护业务数据（如部门、位置）又能准确同步财务数据的导入机制。

## 决策
我们决定实现设备批量导入 v4 版本，采用以下核心架构：

### 1. 四级匹配策略 (Four-Level Matching)
为了精准定位设备记录，按以下优先级执行匹配：
1.  **复合主键匹配**：`(asset_no + department_id + location_text)` 精确匹配。
2.  **设备位号匹配**：`equipment_tag` 全局唯一匹配。
3.  **模糊匹配**：`(name + department_id + location_text)` 组合匹配（仅在无资产编号且无位号时启用）。
4.  **创建新记录**：所有匹配失败时创建新设备。

### 2. 分级更新与保护逻辑 (Graded Update & Protection)
我们将字段分为两类，实施不同的更新策略：
*   **A类字段（财务核心）**：`current_cost`, `book_value`。总是更新，并将空字符串 `""` 自动转换为 `NULL` 以反映未知状态。
*   **B类字段（业务配置）**：`department_id`, `location_text`, `name`, `equipment_tag`, `responsible_person_name`。
    *   **保护机制**：仅当数据库中该字段为 `NULL` 或开启“强制覆盖”模式时才更新。
    *   **模糊匹配限制**：当通过模糊匹配找到设备时，系统强制关闭 B 类字段更新，仅同步 A 类财务数据，防止误改业务信息。

### 3. 结构化警告与审计 (Structured Warnings & Audit)
*   **警告体系**：所有异常场景（如位号冲突、模糊匹配成功、部门映射失败）均返回结构化的 `WarningInfo` 对象 `{field, level, message}`。
*   **审计日志**：创建 `import_audit_logs` 表，记录每一行的操作类型、匹配策略、变更详情及警告信息，满足财务追溯需求。

### 4. 容错与性能 (Fault Tolerance & Performance)
*   **部分成功模式**：采用逐行处理配合 `savepoint` 机制。单行错误仅回滚该行事务，不影响整体导入进度。
*   **重复检测优化**：在解析阶段检测 Excel 内部重复，兼容 `department_id` 和 `department_name` 等多种字段名。
*   **批量提交**：每处理 100 条记录执行一次 `commit`，平衡内存占用与 I/O 性能。

## 后果

### 正面影响
*   **数据安全性提升**：通过 B 类字段保护逻辑，避免了因 Excel 数据陈旧而覆盖用户手动修正的业务信息。
*   **财务合规性**：完整的审计日志和 NULL 值处理确保了财务重估过程的可追溯性和准确性。
*   **灵活性增强**：模糊匹配和位号匹配解决了大量无资产编号设备的录入难题。

### 负面影响
*   **复杂度增加**：四级匹配和分级更新逻辑比 v3 复杂，增加了维护成本。
*   **类型约束严格**：引入 `TypedDict` 虽然提升了可维护性，但在处理动态 Excel 列名时需要更严谨的预处理。

## 变更记录 (2026-09-08)

### 决策变更：资产编号唯一性约束解除
*   **背景**：业务场景中存在“同资产编号、不同物理位置”的设备（如 distributed monitoring systems）。
*   **变更**：移除了数据库层面的 `uq_equipments_asset_no` 唯一性约束。
*   **新规则**：`asset_no` 现作为业务参考号而非全局唯一标识。匹配逻辑升级为优先匹配 `(asset_no + location)`，若位置不匹配则回退至仅匹配 `asset_no` 并记录审计警告。
*   **影响**：允许同一资产编号在台账中存在多条记录，但需通过位置或部门进行区分。
